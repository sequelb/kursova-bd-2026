# ВИСНОВКИ

У рамках курсової роботи спроектовано та реалізовано інформаційну систему для управління навчальною онлайн-платформою. Система забезпечує повний цикл взаємодії між трьома ролями користувачів — студентом, викладачем та адміністратором — та охоплює три бізнес-процеси: продаж навчальних курсів, проходження навчальних матеріалів із автоматичним відстеженням прогресу та виплату винагороди викладачам.

Базу даних спроектовано у СУБД PostgreSQL із дотриманням третьої нормальної форми. Схема містить 11 таблиць (при обмеженні 8–12) із максимальною кількістю 8 стовпців на таблицю (при обмеженні до 10). Цілісність даних забезпечується на рівні бази даних: обмеження CHECK контролюють допустимі значення статусів, ролей та рівнів складності; обмеження UNIQUE запобігають повторному запису студента на курс та повторному призначенню категорії; зовнішні ключі з політиками ON DELETE RESTRICT та ON DELETE CASCADE забезпечують референтну цілісність.

Автоматизацію бізнес-логіки на рівні бази даних реалізовано за допомогою 3 тригерів та 2 допоміжних процедур мовою PL/pgSQL (при вимозі 3–5). Тригер перерахунку прогресу навчання автоматично обчислює відсоток завершених уроків при кожній зміні таблиці прогресу. Два фінансових тригери перераховують баланс викладача при зміні статусу оплат та виплат, делегуючи обчислення спільній допоміжній функції. Такий підхід гарантує узгодженість похідних значень незалежно від способу модифікації базових таблиць — через API, програму-завантажувач або безпосередньо в СУБД.

Для оптимізації типових запитів, що формуються інтерфейсом, створено 5 явних індексів (при вимозі 3–5) на стовпцях зовнішніх ключів, за якими найчастіше виконуються вибірки: курси викладача, записи студента, аналітика курсу, оплати та виплати.

Початкове завантаження даних реалізовано окремою програмою-завантажувачем, що зчитує інформацію про курси з відкритого набору даних Udemy Courses (платформа Kaggle) та генерує пов'язані записи за визначеними правилами. Загальний обсяг тестових даних перевищує 50 000 записів (при вимозі від 1 000), що дозволяє перевірити роботу системи з реалістичними обсягами.

Як додаткову функцію обробки даних реалізовано алгоритм підбору рекомендованих курсів на основі методу видобування асоціативних правил. Алгоритм аналізує шаблони спільних реєстрацій студентів та обчислює композитну оцінку для кожного курсу-кандидата, поєднуючи п'ять сигналів: впевненість та підйом асоціативного правила, вагу завершення однокурсниками спільного курсу, якість рейтингу та афінність категорій. Для студентів без жодного запису передбачено механізм обробки холодного старту з поверненням найпопулярніших курсів. Кожна рекомендація супроводжується текстовим поясненням, що забезпечує прозорість роботи алгоритму для кінцевого користувача.

Серверну частину побудовано на ASP.NET Core 9 Web API із використанням Entity Framework Core 9 як ORM. Автентифікацію реалізовано на основі файлів cookie без використання ASP.NET Identity, що дозволило зберегти схему бази даних у межах встановлених обмежень. Клієнтську частину побудовано як односторінковий вебзастосунок на React 18 із TypeScript, TanStack Query для управління серверним станом та Recharts для візуалізації аналітичних даних.

## Встановлені недоліки

а) *Відсутність функції видалення відгуків адміністратором та викладачем.* Наразі видалити відгук може лише його автор-студент. Для повноцінної модерації контенту необхідно додати можливість видалення відгуків адміністратором, а також механізм для викладача позначати відгуки як неприйнятні;

б) *Спрощена модель оплати.* Оплата фіксується як факт без інтеграції з зовнішніми платіжними системами. Комісія платформи не враховується — увесь дохід від курсу зараховується викладачу, що не відповідає реальним бізнес-моделям;

в) *Текстовий формат уроків.* Контент уроків обмежений текстом. Підтримка відео, зображень або інтерактивних елементів потребує розширення схеми та інтеграції з інфраструктурою зберігання файлів;

г) *Відсутність сповіщень.* Система не інформує користувачів про події (новий запис на курс, зміна статусу виплати) поза межами поточної сесії браузера.

## Перспективи покращення

а) *Розширення модерації контенту.* Додати можливість видалення та приховування відгуків адміністратором, механізм скарг на контент та відповідний інтерфейс для розгляду скарг;

б) *Комісія платформи.* Додати стовпець platform_fee до таблиці payments, оновити тригер обчислення балансу та додати показник «Прибуток платформи» до фінансової панелі адміністратора;

в) *Мультимедійний контент.* Розширити модель уроків для підтримки різних типів контенту (відео, зображення, фрагменти коду), що потребує інтеграції з файловим сховищем;

г) *Кешування рекомендацій.* Для масштабування алгоритму рекомендацій на великих обсягах даних можна застосувати матеріалізоване представлення (materialized view) або окрему таблицю з періодичним оновленням замість обчислення при кожному запиті;

ґ) *Розширення аналітики.* Додати порівняльні звіти між курсами, аналіз утримання студентів, прогнозування доходу та експорт аналітичних даних у зовнішні формати.
